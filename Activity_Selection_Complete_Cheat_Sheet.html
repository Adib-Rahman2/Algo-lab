Activity selection cheat sheet

Activity Selection

The greedy algorithm for scheduling the maximum number of non-overlapping activities in one resource: earliest finish time first, its proof, dry runs with timelines, and every exam variation from meeting rooms and time strings to minimum removals, interval partitioning and the weighted version.

Sort activities by finish time f1 ≤ f2 ≤ … ≤ fn.
Select a1; then repeatedly select the next am with sm ≥ f of the last selected activity.
Time Θ(n log n) for sorting + Θ(n) scan. Space O(1) extra (O(n) for indices).

Scheduling lab: check any exam answer

Enter activities as start-finish, optionally with a name first, separated by commas: 1-4, 3-5, 0-6 or Math 09:00-10:30, Chess 10:30-12:00. The timeline, greedy trace, answer, minimum removals and rooms needed appear below.

1. Fundamentals

What the problem is and why it is used

You are given n activities S = {a1, …, an} that all need the same single resource (a lecture hall, a machine, one person). Activity ai occupies the half-open interval [si, fi). Two activities are compatible if their intervals do not overlap. The activity selection problem asks for a maximum-size set of mutually compatible activities.

It models room booking, single-machine job scheduling, choosing TV programmes or conference talks to attend, and allocating a shared channel. It is the standard first example of a greedy algorithm in CLRS (Chapter 15/16 depending on edition) and in Kleinberg–Tardos (“interval scheduling”).

Core intuition Among all activities, the one that finishes first leaves the most time for everything else. Choosing it can never hurt, so take it, throw away everything that overlaps it, and repeat.

Terminology

TermMeaning
Start time si, finish time fi0 ≤ si < fi. The activity uses [si, fi).
Compatible (non-overlapping)ai, aj compatible ⇔ si ≥ fj or sj ≥ fi. With half-open intervals an activity may start exactly when another ends.
Closed-interval conventionSome questions treat [s, f] as closed: then touching is a conflict and the test becomes si > fj. Read the question.
Mutually compatible setEvery pair in the set is compatible (equivalently, sorted by start, each starts at or after the previous one finishes).
Maximum-size vs maximum-weightActivity selection maximises the count. Maximising total value/profit/duration is weighted interval scheduling (DP, not greedy).
SkActivities that start after ak finishes: {ai : si ≥ fk}.
Sij (CLRS DP)Activities that start after ai finishes and finish before aj starts.

When to use it and when not to

Use earliest-finish greedy when
  • There is one resource and each activity has a fixed start and finish.
  • Every activity is equally valuable and you maximise how many are done.
  • The question asks for the maximum number of non-overlapping intervals, the minimum number to remove, or the minimum number of points that hit every interval (same greedy).
Do not use it when
  • Activities have different profits/weights → weighted interval scheduling (DP + binary search).
  • You must schedule all activities using as few rooms as possible → interval partitioning (sort by start, min-heap).
  • Jobs have deadlines and durations but no fixed start → job sequencing / scheduling to minimise lateness.
  • Activities can be moved or split → different problems entirely.

Advantages, limitations, typical pitfalls

AdvantagesLimitations
Simple, O(n log n), O(n) if already sorted. Provably optimal. Easy to trace by hand and to code from memory. Same pattern solves several interval problems. Only maximises the count for one resource. The optimal set is often not unique (greedy finds one of them). Fails for weights. Results depend on the endpoint convention (touching allowed or not). Natural-looking alternatives (earliest start, shortest duration, fewest conflicts) are wrong.

2. The greedy algorithm, its correctness and complexity

Pseudocode (CLRS)

GREEDY-ACTIVITY-SELECTOR(s, f)          ▷ activities sorted by f
  n ← s.length
  A ← {a1}
  k ← 1                                  ▷ index of last selected
  for m ← 2 to n
      if s[m] ≥ f[k]
          A ← A ∪ {am}
          k ← m
  return A

RECURSIVE-ACTIVITY-SELECTOR(s, f, k, n)  ▷ call with k = 0, f[0] = 0
  m ← k + 1
  while m ≤ n and s[m] < f[k]          ▷ skip activities that start too early
      m ← m + 1
  if m ≤ n
      return {am} ∪ RECURSIVE-ACTIVITY-SELECTOR(s, f, m, n)
  else return ∅

If the input is not sorted by finish time, sort first (carry original indices along so you can report the right activities).

Correctness proof

Theorem (greedy choice, CLRS 16.1). For any non-empty subproblem Sk, let am be the activity in Sk with the earliest finish time. Then am belongs to some maximum-size compatible subset of Sk.

Proof (exchange argument)

Let Ak be a maximum-size compatible subset of Sk and let aj be the activity in Ak with the earliest finish time. If aj = am, done. Otherwise let A′ = (Ak − {aj}) ∪ {am}.

Every other activity in Ak starts at or after fj (they are compatible with aj and finish later). Since fm ≤ fj, they also start at or after fm, so A′ is compatible. |A′| = |Ak|, so A′ is also maximum and contains am.

Optimal substructure: after choosing am, the remaining problem is exactly Sm (activities starting after fm), and an optimal solution of Sk containing am is {am} ∪ (an optimal solution of Sm). By induction the greedy algorithm is optimal.

Alternative proof: “greedy stays ahead” (Kleinberg–Tardos)

Let greedy pick i1, …, ik and an optimal solution j1, …, jm, both in finish order. Claim: f(ir) ≤ f(jr) for all r ≤ k. True for r = 1 (greedy picks the earliest finish overall). If true for r − 1, then jr starts after f(jr−1) ≥ f(ir−1), so jr was available to greedy at step r; greedy picks the earliest-finishing available one, so f(ir) ≤ f(jr).

If m > k, activity jk+1 starts after f(jk) ≥ f(ik), so greedy would not have stopped: contradiction. Hence k = m.

The DP formulation (why greedy is better)

c[i, j] = 0 if Sij = ∅
c[i, j] = maxak ∈ Sij { c[i, k] + c[k, j] + 1 } otherwise

This DP is correct but takes O(n3) time. A simpler O(n2) DP sorts by finish and sets dp[i] = 1 + max dp[j] over compatible j < i. The greedy theorem shows that only one choice (earliest finish) needs to be tried, collapsing the DP to one pass. Program a10 implements the O(n2) DP and was used to cross-check the greedy answers on this sheet.

Dry run 7: why other greedy rules fail

Earliest start first

Rows sorted by finish time. Filled bars = selected by earliest-finish greedy; dashed bars = rejected.

Earliest start picks Long (0, 10) and blocks both short ones → 1. Earliest finish picks Short1, Short2 → 2.

Shortest duration first

Rows sorted by finish time. Filled bars = selected by earliest-finish greedy; dashed bars = rejected.

Shortest picks Middle (4, 7) (length 3), which overlaps both others → 1. Optimal: Left, Right → 2.

Fewest conflicts first

Rows sorted by finish time. Filled bars = selected by earliest-finish greedy; dashed bars = rejected.

Conflict counts: X overlaps only B and C (2 conflicts, the unique minimum); A and D have 3; every other activity has 4. Fewest-conflicts picks X first, which kills B and C, leaving at most A (or a P) and D (or a Q): total 3. The optimum is A, B, C, D = 4, exactly what earliest-finish finds.

4. Converting story problems into activity selection

  1. Find the intervals. Anything with a start and an end: meetings, lectures, shows, jobs, bookings, trips, advertisements, sensor windows.
  2. Count the resources. One room / one person / one machine → activity selection. Several rooms and “schedule all” → interval partitioning. k rooms and “maximise how many” → k-resource variant.
  3. Check the objective. “Maximum number”, “as many as possible”, “minimum to cancel/remove” → earliest-finish greedy. “Maximum profit/pay/value/total duration” → weighted DP.
  4. Fix the endpoint rule. Can a new activity start exactly when one ends? Is there a required gap (travel, setup)?
  5. Normalise the input. Convert times to minutes, durations to finish times (f = s + d), and keep names/indices before sorting.

Worked translations

A. Direct start/finish arrays

“Given s = ⟨1, 3, 0, 5, 3, 5, 6, 8, 8, 2, 12⟩ and f = ⟨4, 5, 6, 7, 9, 9, 10, 11, 12, 14, 16⟩, find a maximum set of mutually compatible activities.” Already standard: Dry run 1.

B. One seminar hall, many requests

“A university has one seminar hall. Clubs request it for: Robotics 9–11, Drama 10–12, Music 11–13, Chess 12–14, Debate 13–15, Art 9–15. Grant the maximum number of requests.”

Extract: one resource, equal value, maximise count. Sorted by finish: Robotics 11, Drama 12, Music 13, Chess 14, Debate 15, Art 15. Select Robotics (ends 11), Music (11 ≥ 11, ends 13), Debate (13 ≥ 13). Answer: 3 (Robotics, Music, Debate).

C. A student at a festival (clock times)

“A student wants to attend as many events as possible: Math 09:00–10:30, Physics 10:00–11:00, Chess 10:30–12:00, Lunch 12:00–13:00, Debate 11:30–12:30.” Convert to minutes: Dry run 4 → Math, Chess, Lunch.

D. Single machine with start and duration

“A 3D printer can run one job at a time. Jobs: J1 starts 0 for 3 h, J2 starts 2 for 2 h, J3 starts 3 for 4 h, J4 starts 5 for 1 h, J5 starts 6 for 2 h. Maximise completed jobs.”

Extract: f = s + d: J1 [0, 3), J2 [2, 4), J3 [3, 7), J4 [5, 6), J5 [6, 8). Sort by finish: J1 3, J2 4, J4 6, J3 7, J5 8. Select J1 (3), J2 rejected (2 < 3), J4 (5 ≥ 3, ends 6), J3 rejected (3 < 6), J5 (6 ≥ 6). Answer: 3 (J1, J4, J5).

E. TV channel advertisements (count removals)

“Ad slots requested: [1, 2], [2, 3], [3, 4], [1, 3]. Overlapping ads cannot both air. What is the minimum number of ads to reject?”

Minimum removals = n − (maximum compatible). Greedy keeps [1,2], [2,3], [3,4] → remove 1.

F. How many rooms are needed? (not activity selection)

“All six lectures must take place: (1, 2), (3, 4), (0, 6), (5, 7), (8, 9), (5, 9). What is the minimum number of classrooms?”

“All must happen” + “minimum rooms” = interval partitioning. Answer = maximum number of lectures overlapping at one moment = 3 (at time 5.5: (0, 6), (5, 7), (5, 9)). See Variation V8.

G. Freelancer gigs with pay (weighted, not greedy)

“Gigs (start, end, pay): (1, 3, 5), (2, 5, 6), (4, 6, 5), (6, 7, 4), (5, 8, 11), (7, 9, 2). Maximise total pay.”

Different pays → weighted interval scheduling. Earliest-finish greedy would take (1, 3), (4, 6), (6, 7), (7, 9) = 5 + 5 + 4 + 2 = 16, but the optimum is (2, 5) + (5, 8) = 17. See V9.

H. Balloons and arrows (interval stabbing)

“Balloons span x-ranges [10, 16], [2, 8], [1, 6], [7, 12]. An arrow shot at x bursts all balloons covering x. Minimum arrows?”

Sort by right end; shoot at the right end of the first unburst balloon. Arrows at 6 and 12 → 2. The number of arrows equals the maximum number of pairwise disjoint balloons (same greedy).

I. Travel or setup time between activities

“A technician needs 1 hour to travel between sites. Jobs: [1, 3], [3, 5], [6, 8]. How many can be done?”

Compatibility becomes s ≥ last finish + gap. [1, 3] → ready at 4; [3, 5] rejected; [6, 8] accepted → 2. Same greedy, modified test (V12).

J. Two identical rooms, maximise bookings

“There are 2 rooms. From the CLRS 11 activities, how many can be scheduled?”

k-resource variant (V10): process by finish time; put each activity in the room that became free latest but still before its start. Answer: 6.

Core variations

V1. Maximum number of activities, print them the standard problem
Looks like
“Given start and finish times of n activities, select the maximum number that can be performed by a single person.”
Recognise
One resource, “maximum number”, “mutually compatible”, “non-overlapping”.
Input
n, array s, array f (possibly unsorted).
Output
The count and the chosen activities.
Approach
Sort indices by finish (stable), scan, take an activity if s ≥ last finish.
Steps
Dry run 1.
Complexity
O(n log n) time, O(n) space for indices.
Edge cases
n = 0 → 0. n = 1 → 1. All overlapping → 1. None overlapping → n. Initialise last finish to −∞ (or use “first activity always selected”), not 0 if times can be negative.
a01_greedy.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> s(n), f(n);
    for (auto &x : s) cin >> x;
    for (auto &x : f) cin >> x;

    vector<int> idx(n);
    iota(idx.begin(), idx.end(), 0);
    stable_sort(idx.begin(), idx.end(), [&](int a, int b) { return f[a] < f[b]; });

    vector<int> chosen;
    int lastFinish = INT_MIN;
    for (int i : idx)
        if (s[i] >= lastFinish) {
            chosen.push_back(i);
            lastFinish = f[i];
        }

    cout << "Maximum activities: " << chosen.size() << "\n";
    for (int i : chosen) cout << "a" << i + 1 << " [" << s[i] << ", " << f[i] << ")\n";
}

Looks like
“Each line has an event name, start time and end time in HH:MM. Print the schedule with the most events.”
Recognise
Strings with colons; names to report.

a02_named_times.cpp
#include <bits/stdc++.h>
using namespace std;

int toMinutes(const string &t) {
    int h, m;
    char colon;
    stringstream ss(t);
    ss >> h >> colon >> m;
    return h * 60 + m;
}

struct Event {
    string name;
    int start, finish;
    string s, f;
};

int main() {
    int n;
    cin >> n;
    vector<Event> e(n);
    for (auto &x : e) {
        cin >> x.name >> x.s >> x.f;
        x.start = toMinutes(x.s);
        x.finish = toMinutes(x.f);
    }
    stable_sort(e.begin(), e.end(), [](const Event &a, const Event &b) { return a.finish < b.finish; });

    int last = INT_MIN, count = 0;
    for (auto &x : e)
        if (x.start >= last) {
            cout << x.name << " " << x.s << "-" << x.f << "\n";
            last = x.finish;
            count++;
        }
    cout << "Total: " << count << "\n";
}

V3. Recursive version (CLRS RECURSIVE-ACTIVITY-SELECTOR) “write the recursive algorithm”
Looks like
“Write a recursive greedy algorithm for activity selection and analyse it.”
Approach
Fictitious activity a0 with f0 = 0; from k, skip m while sm < fk; select m; recurse from m.
Steps
CLRS data: k = 0 → m = 1 (a1); k = 1 → skip a2, a3 → a4; k = 4 → skip a5–a7 → a8; k = 8 → skip a9, a10 → a11; k = 11 → stop.
Complexity
Θ(n) total (each m examined once across all calls), assuming sorted input.
Edge cases
Requires sorted input. f0 = 0 only works if all starts are ≥ 0.
a03_recursive.cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> s, f;
vector<int> A;

void recursiveSelector(int k, int n) {
    int m = k + 1;
    while (m <= n && s[m] < f[k]) m++;
    if (m <= n) {
        A.push_back(m);
        recursiveSelector(m, n);
    }
}

int main() {
    int n;
    cin >> n;
    s.assign(n + 1, 0);
    f.assign(n + 1, 0);
    for (int i = 1; i <= n; i++) cin >> s[i];
    for (int i = 1; i <= n; i++) cin >> f[i];
    recursiveSelector(0, n);
    cout << A.size() << ":";
    for (int i : A) cout << " a" << i;
    cout << "\n";
}

V4. Symmetric greedy: latest start time first “another greedy that works”
Looks like
“Show that selecting the activity that starts last is also optimal.” (CLRS 16.1-4/15.1-4 style)
Approach
Mirror image of earliest finish: sort by start descending; take an activity if its finish ≤ the start of the last chosen.
Steps
On CLRS data it picks a11 (12), a8 (8), a4 (5), a2 (3) → {a2, a4, a8, a11}, also 4.
Complexity
O(n log n).
Edge cases
It may return a different maximum set than earliest finish; both are correct.
a04_latest_start.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> a(n);
    for (auto &[s, f] : a) cin >> s >> f;
    sort(a.begin(), a.end(), [](auto &x, auto &y) { return x.first > y.first; });
    int boundary = INT_MAX;
    vector<pair<int, int>> chosen;
    for (auto &[s, f] : a)
        if (f <= boundary) {
            chosen.push_back({s, f});
            boundary = s;
        }
    reverse(chosen.begin(), chosen.end());
    cout << chosen.size() << ":";
    for (auto &[s, f] : chosen) cout << " [" << s << "," << f << ")";
    cout << "\n";
}

#include <bits/stdc++.h>

V8. Interval partitioning: minimum rooms to schedule all “minimum classrooms / platforms”
Looks like
“All lectures must be held. Find the minimum number of lecture halls.” “Minimum platforms for trains with arrival/departure times.”
Recognise
“all”, “minimum number of rooms/resources”.
Approach
Sort by start. Keep a min-heap of room free times; reuse the room that frees earliest if it is free by s, else open a new room. Answer = maximum overlap (depth).
Steps
(1, 2), (3, 4), (0, 6), (5, 7), (8, 9), (5, 9): 3 rooms.
Complexity
O(n log n).
Edge cases
Sorting by finish here is wrong. Equal end/start: process the end first (half-open) so the room is reused; for platforms where a train arriving when another departs still needs a platform, process starts first.

#include <bits/stdc++.h>

int main() {
    int n;

        cin >> a[i][0] >> a[i][1];
        a[i][2] = i;

            busy.pop();

            r = ++rooms;

        room[id] = r;
        busy.push({f, r});
    }
    cout << "Rooms needed: " << rooms << "\n";
    for (int i = 0; i < n; i++) cout << "activity " << i + 1 << " -> room " << room[i] << "\n";
}

V9. Weighted interval scheduling “maximum profit”
Looks like
“Each job has start, finish and profit. Maximise total profit of non-overlapping jobs.”
Recognise
Values differ: profit, pay, priority, duration as value.
Approach
Sort by finish. p(k) = number of jobs finishing ≤ sk (binary search). dp[k] = max(dp[k − 1], wk + dp[p(k)]). Trace back to list the jobs.
Steps
Gigs example (story G): 17 with jobs 2 and 5.
Complexity
O(n log n).
Edge cases
When all weights are equal it reduces to activity selection. Use upper_bound on finishes (≤ s) for half-open intervals.
a07_weighted.cpp
#include <bits/stdc++.h>
using namespace std;

struct Job { int s, f; long long w; int id; };

int main() {
    int n;
    cin >> n;
    vector<Job> j(n);
    for (int i = 0; i < n; i++) { cin >> j[i].s >> j[i].f >> j[i].w; j[i].id = i + 1; }
    sort(j.begin(), j.end(), [](const Job &a, const Job &b) { return a.f < b.f; });

    vector<int> finish(n);
    for (int i = 0; i < n; i++) finish[i] = j[i].f;
    vector<int> p(n + 1);
    vector<long long> dp(n + 1, 0);
    for (int k = 1; k <= n; k++) {
        p[k] = upper_bound(finish.begin(), finish.begin() + (k - 1), j[k - 1].s) - finish.begin();
        dp[k] = max(dp[k - 1], j[k - 1].w + dp[p[k]]);
    }

    vector<int> chosen;
    for (int k = n; k > 0;) {
        if (j[k - 1].w + dp[p[k]] > dp[k - 1]) { chosen.push_back(j[k - 1].id); k = p[k]; }
        else k--;
    }
    reverse(chosen.begin(), chosen.end());
    cout << "Maximum weight: " << dp[n] << "\nJobs:";
    for (int id : chosen) cout << " " << id;
    cout << "\n";
}

V10. k identical resources, maximise the number Advanced
Looks like
“There are k rooms; schedule as many activities as possible.”
Approach
Process by finish. Among rooms free by s, use the one whose last finish is latest (best fit). If none is free but fewer than k rooms are used, open one. Otherwise skip.
Steps
CLRS data, k = 2 → 6.
Complexity
O(n log k) with a multiset.
Edge cases
Using the earliest-free room instead of the latest-free one can lose activities. Checked against brute force on random inputs.
a08_k_rooms.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<pair<int, int>> a(n);
    for (auto &[s, f] : a) cin >> s >> f;
    sort(a.begin(), a.end(), [](auto &x, auto &y) { return x.second < y.second; });
    multiset<int> lastFinish;
    int count = 0;
    for (auto &[s, f] : a) {
        auto it = lastFinish.upper_bound(s);
        if (it != lastFinish.begin()) {
            lastFinish.erase(prev(it));
            lastFinish.insert(f);
            count++;
        } else if ((int)lastFinish.size() < k) {
            lastFinish.insert(f);
            count++;
        }
    }
    cout << "Maximum activities with " << k << " rooms: " << count << "\n";
}

Looks like

Sort by right end; place a point at the right end of the first interval not yet hit; skip all intervals containing it.

V12. Interval covering: fewest intervals to cover [L, R] different greedy
Looks like
“Choose the minimum number of shifts (or sprinklers, or video clips) that cover the whole period [L, R].”
Approach
Sort by start. Repeatedly, among intervals starting ≤ current covered point, take the one reaching farthest.
Steps
[0, 10] with (0, 3), (2, 6), (3, 4), (6, 10), (5, 9) → (0, 3), (2, 6), (6, 10) = 3.
Complexity
O(n log n).
Edge cases
Gap → impossible. This greedy picks by farthest reach, not by earliest finish.
a11_cover.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, L, R;
    cin >> n >> L >> R;
    vector<pair<int, int>> a(n);
    for (auto &[s, f] : a) cin >> s >> f;
    sort(a.begin(), a.end());
    int covered = L, used = 0, i = 0;
    while (covered < R) {
        int best = covered;
        while (i < n && a[i].first <= covered) best = max(best, a[i++].second);
        if (best == covered) { cout << "Impossible to cover [" << L << ", " << R << "]\n"; return 0; }
        covered = best;
        used++;
    }
    cout << "Minimum intervals: " << used << "\n";
}

A1. Online / streaming arrival, DP on time axis, and other extensions Beyond typical syllabus

Integer times in a small range: dp[t] = max(dp[t − 1], max over activities ending at t of dp[s] + 1) gives O(n + T). Online arrival: no algorithm can be optimal without knowing the future; competitive analysis applies. Activities on a circle (shifts crossing midnight repeatedly): try each activity as the first one or cut the circle, O(n2) or O(n log n) with doubling. Maximum total duration = weighted with weight = f − s (V9).

8. Exam question bank with solutions

All answers checked by program.

Level 1: Basic

Q1. Apply GREEDY-ACTIVITY-SELECTOR to the CLRS 11 activities.

Dry run 1: {a1, a4, a8, a11}, 4 activities.

Q2. s = [1, 3, 0, 5, 8, 5], f = [2, 4, 6, 7, 9, 9]. Maximum activities?

Sorted order a1, a2, a3, a4, a5, a6. Select a1 (2), a2 (3 ≥ 2), skip a3, a4 (5 ≥ 4), a5 (8 ≥ 7), skip a6 → 4.

Q3. Meetings [10, 20), [12, 25), [20, 30). How many fit in one room?

[10, 20) then [20, 30) (starts exactly at 20) → 2.

Q4. What is the time complexity and why?

Θ(n log n) to sort by finish, then Θ(n) for one scan. If already sorted: Θ(n).

Q5. Why sort by finish time rather than start time?

The earliest finish leaves the maximum remaining time (exchange argument). Earliest start fails: (0, 10), (1, 2), (3, 4).

Q6. Minimum intervals to remove from [1, 2], [2, 3], [3, 4], [1, 3] so the rest do not overlap.

Greedy keeps 3, so remove 4 − 3 = 1 (the interval [1, 3]).

Level 2: Intermediate

Q7. Unsorted: A(3, 5), B(1, 4), C(0, 6), D(5, 7), E(3, 8), F(5, 9), G(6, 10), H(8, 11), I(8, 12), J(2, 13), K(12, 14). Show the sorted table and the selection.

Sorted by finish: B 4, A 5, C 6, D 7, E 8, F 9, G 10, H 11, I 12, J 13, K 14. Select B (4); A (3 < 4) no; C no; D (5 ≥ 4) yes, last 7; E, F, G no; H (8 ≥ 7) yes, last 11; I, J no; K (12 ≥ 11) yes. Answer: B, D, H, K = 4.

Q8. [1, 4], [4, 6], [6, 8], [2, 5], [5, 7]: answer under half-open and closed conventions.

Half-open: [1, 4], [4, 6], [6, 8] → 3. Closed (touching conflicts): [1, 4], [5, 7] → 2.

Q9. Trace RECURSIVE-ACTIVITY-SELECTOR on the CLRS data. How many times is the while-loop test evaluated in total?

Calls with k = 0, 1, 4, 8, 11. Tests: k=0: m=1, test fails at once → 1 test; k=1: m=2,3 fail, m=4 ok → 3 tests; k=4: m=5,6,7 fail, 8 ok → 4; k=8: m=9,10 fail, 11 ok → 3; k=11: m=12 > n the m ≤ n check fails → 1. Total 1 + 3 + 4 + 3 + 1 = 12 tests: every activity is examined once, plus one final check, so Θ(n).

Q10. Run the latest-start-first greedy on the CLRS data.

a11 (start 12), then the latest start with finish ≤ 12 is a8 (8, 11), then a4 (5, 7) finishes ≤ 8, then a2 (3, 5) finishes ≤ 5 → {a2, a4, a8, a11}, 4.

Q11. A printer job list gives start and duration: (0, 3), (2, 2), (3, 4), (5, 1), (6, 2). Maximum jobs?

Finish = start + duration: [0,3), [2,4), [3,7), [5,6), [6,8). Greedy picks [0,3), [5,6), [6,8) → 3.

Q12. Prove with an example that “shortest activity first” is not optimal.

(0, 5), (4, 7), (6, 11): the shortest (4, 7) overlaps both others → 1; optimal (0, 5), (6, 11) → 2.

Level 3: Advanced

Q13. All CLRS activities must be scheduled. Minimum number of rooms?

Maximum overlap: in [8, 9) activities a5, a6, a7, a8, a9, a10 are all active → 6 rooms.

Q14. Gigs (s, f, pay): (1, 3, 5), (2, 5, 6), (4, 6, 5), (6, 7, 4), (5, 8, 11), (7, 9, 2). Maximum pay. Does earliest-finish greedy work?

DP gives 17 (gigs 2 and 5). Greedy by finish gives 4 gigs worth 16. Weights break the greedy.

Q15. With 2 identical rooms, how many CLRS activities can be scheduled?

6 (best-fit greedy by finish, verified by brute force).

Q16. Minimum arrows for balloons [10, 16], [2, 8], [1, 6], [7, 12].

Sorted by right end: [1,6], [2,8], [7,12], [10,16]. Arrow at 6 bursts [1,6], [2,8]; arrow at 12 bursts [7,12], [10,16] → 2.

Q17. Cover [0, 10] with (0, 3), (2, 6), (3, 4), (6, 10), (5, 9) using the fewest intervals.

From 0: best reach 3 (0, 3). From 3: candidates (2, 6), (3, 4) → 6. From 6: (6, 10), (5, 9) → 10. Total 3.

Q18. Story: a technician needs 1 hour of travel between jobs [1, 3], [3, 5], [6, 8]. Maximum jobs?

Test s ≥ f + 1: [1, 3] → ready 4; [3, 5] rejected; [6, 8] accepted → 2.

Q19. Prove the “greedy stays ahead” lemma f(ir) ≤ f(jr).

Induction on r (Section 2): base r = 1 from the earliest-finish choice; step: jr is compatible with greedy’s first r − 1 picks, so it was a candidate, and greedy chose the earliest finishing candidate.

Q20. Programming: read events as “name HH:MM HH:MM”, print the maximum schedule in time order.

Program a02 (V2). Selected events are printed in finish order, which is also chronological.

Q21. A night-shift booking runs 22:00–02:00. How do you handle it?

Convert to minutes on a continuous axis: 22:00 = 1320, 02:00 next day = 1440 + 120 = 1560. If schedules repeat daily (circular), that is the circular variant (A1).

Q22. Does a maximum set always contain the activity with the earliest finish? Does it always contain the shortest one?

Some maximum set always contains the earliest-finishing activity (the theorem), but not every maximum set does. The shortest activity need not be in any maximum set (Q12).

Q23. Programming: given n intervals, print the maximum compatible count, the minimum removals and the minimum rooms.

Combine a01 (count), n − count, and a06 (rooms). The lab at the top of this sheet computes all three for any input.

11. Quick revision sheet

Core rule
Sort by f ascending.
Take a1; then take am if sm ≥ flast.
Min removals = n − count.
Min rooms (all) = maximum overlap.
Complexity Θ(n log n) sort + Θ(n) scan; Θ(n) if sorted; recursive Θ(n); DP O(n2) or O(n3); weighted O(n log n).
Proof in two lines Exchange: the earliest-finishing activity can replace the first activity of any optimal solution. Then the rest is the same problem on Sm.
Counterexamples Earliest start: (0,10), (1,2), (3,4). Shortest: (0,5), (4,7), (6,11). Fewest conflicts: 11-interval example. Weighted: (1,3,1), (2,5,100).
Key observations
  • One resource + count → greedy by finish. Weights → DP. All activities + min rooms → sort by start.
  • Count is unique, the set is not. Latest-start-first is the mirror greedy and also works.
  • Selected activities are automatically in chronological order.
  • State the endpoint convention; it changes answers.
Recognition keywords maximum number of activities · single room / person · non-overlapping · mutually compatible · minimum to remove · can start when previous ends.

Standard template to write from memory

activity_template.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> s(n), f(n), idx(n);
    for (auto &x : s) cin >> x;
    for (auto &x : f) cin >> x;
    iota(idx.begin(), idx.end(), 0);
    stable_sort(idx.begin(), idx.end(), [&](int a, int b) { return f[a] < f[b]; });
    vector<int> chosen;
    int last = INT_MIN;
    for (int i : idx)
        if (s[i] >= last) { chosen.push_back(i); last = f[i]; }
    cout << chosen.size() << "\n";
    for (int i : chosen) cout << "a" << i + 1 << " ";
    cout << "\n";
}
Last-minute exam tips
  1. Write the activities in a table sorted by finish time first, keeping original labels.
  2. State the rule (“earliest finish first; compatible if s ≥ last finish”).
  3. Show a decision column: s vs last finish → select / reject.
  4. Draw a timeline if asked to “show” or “illustrate”.
  5. Check the answer: selected intervals must not overlap; count ≤ n; with half-open intervals touching is fine.
  6. If profits appear, stop and use the weighted DP. If “all” and “minimum rooms” appear, sort by start.
  7. For proofs, write the exchange argument; for “show greedy X fails”, use the counterexamples above.
  8. In the lab: test CLRS (4), all overlapping (1), disjoint (n), touching endpoints, n = 0.
